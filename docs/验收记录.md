Go 服务端测试覆盖：注册、登录、重名、弱密码、错误密码、JWT 篡改/过期、未登录访问、未加入用户访问、无效会议号、主持人权限、已结束会议拒绝加入、真实 WebSocket 双客户端、成员状态同步、聊天广播、重发去重、断线游标补齐、新连接替换旧连接、结束广播、不可信 Origin、长消息拒绝、REST 主动离会。

数据库测试写入 205 条消息，验证最近 100 条、向前翻页与 after 补齐；关闭再打开数据库后会议和消息仍存在，并清理残留在线状态。

前端测试覆盖：

1. 麦克风切换停止旧轨道，离会停止所有轨道。
2. 设备权限拒绝时保持静音，并展示可理解提示。
3. 退出后才完成的权限请求不会重新开启设备。
4. 断线进入重连状态，恢复后通过消息游标补齐；卸载/替换事件后停止重连。
5. 回车发送消息，中文输入法组合期间不误发，服务端确认后不重复显示。
6. 成员新会话替换旧 P2P，忽略旧会话信令。
7. SDP/ICE 串行执行，ICE 不越过尚未完成的 SDP。
8. 本地设备断开/恢复时复用 RTCRtpSender。

测试期间没有可用的 C 编译器，`CGO_ENABLED=0`，未运行 Go race detector。常规并发行为由真实 WebSocket 集成测试覆盖；不能将其等同于竞态检测。

## 浏览器双用户验收

用构建后的 Go 服务托管前端，在两个独立标签页中完成以下流程。测试使用临时数据库，不向正式数据库预置账号或演示数据。

| 操作 | 实际观察 |
| --- | --- |
| 注册主持人与参会者 | 两个账号各自登录，昵称正确 |
| 主持人创建会议 | 返回 9 位会议号并进入入会准备页 |
| 静音入会 | 摄像头和麦克风默认关闭，仍可成功加入 |
| 第二账号输入会议号加入 | 双方显示 2 名成员，主持人/本人标识正确 |
| 主持人先发送消息，第二账号随后加入 | 第二账号正常加载既有历史消息 |
| 第二账号发送消息 | 主持人页面实时收到且身份正确 |
| 第二账号离会 | 返回工作台，主持人页面成员数从 2 变为 1 |
| 主持人确认结束会议 | 返回工作台，已结束计数为 1 |
| 切换到已结束列表 | 会议主题、会议号和主持人信息正确保留 |

## 验证边界

- 浏览器验收时未开启真实摄像头/麦克风，不宣称已验证实际声音与视频质量。
- 媒体生命周期和 SDP/ICE 时序由模拟对象测试覆盖，真实 WebRTC 设备与跨网络 NAT 连通性需要设备实测。
- 自动重连和离线消息补齐由前端模拟网络事件、后端真实 WebSocket 断开/重连组合验证；本次没有在浏览器手动切换操作系统网络。
- 未做 SFU、多实例、负载、长时间压力或公网部署测试。P2P 推荐用于 2–4 人演示，复杂网络需配置 TURN。
- 单机 SQLite 结构与初始化适用于当前基础档，后续升级需补充正式数据库迁移。
