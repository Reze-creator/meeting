# 进阶档实现与运行

本次更新在基础档之上完成进阶能力。所有源码继续放在 `D:/Go_WorkSpace/meeting`，保留基础档数据库和接口兼容性。真实 SFU 使用 LiveKit；未配置媒体服务时仍可运行 P2P 演示。

## 一条命令启动完整本机演示

在项目根目录执行：

```powershell
.\scripts\start-advanced.ps1
```

首次运行会从 LiveKit 官方发布页下载固定的 **1.13.11** Windows 包，验证官方 SHA256 清单，并解压到被 Git 忽略的 `bin/livekit`。脚本启动仅绑定本机的 SFU，再安装/构建前端并启动 Go。访问 **http://127.0.0.1:8080**，用两个独立浏览器标签页登录不同账号进行验证。

脚本不修改 PATH、系统网络、安全设置或全局环境变量。LiveKit 子进程隐藏运行，日志写入 `data/livekit.*.log`；退出脚本时只停止本次创建的子进程。如果 7880 已被占用，脚本会停止并说明，避免误用或停止其他服务。

已有自建或云端 LiveKit 时，按 `.env.example` 设置以下值，再使用原来的 `scripts/start.ps1`：

```dotenv
LIVEKIT_URL=ws://127.0.0.1:7880
LIVEKIT_INTERNAL_URL=http://127.0.0.1:7880
LIVEKIT_API_KEY=devkey
LIVEKIT_API_SECRET=comeet-local-development-secret-2026
RECORDING_DIR=data/recordings
MEETING_MAX_MINUTES=240
```

上面的 `devkey/comeet-local-development-secret-2026` 是仅供本机测试的公开值。正式部署必须使用自己的密钥，浏览器地址使用 `wss://`，并确保 ICE TCP/UDP、TURN 和公网地址配置正确。Go 使用 `LIVEKIT_INTERNAL_URL` 调用管理接口，浏览器只接收短期房间令牌，不接收管理密钥。

也可以分两个终端启动：

```powershell
# 终端 A：安装一次后启动 SFU
.\scripts\install-livekit.ps1
.\scripts\start-livekit.ps1

# 终端 B：配置好根目录 .env 后启动应用
.\scripts\start.ps1
```

## 功能与使用方法

| 进阶要求 | 本次实现 | 使用方式 |
| --- | --- | --- |
| 屏幕共享 | 独立屏幕轨道，保留摄像头；浏览器停止按钮同步结束 | 会中点击“共享屏幕”，选择允许共享的窗口；其他人选择共享主画面观看 |
| 麦克风电平 | Web Audio RMS 采样，关闭面板释放 AudioContext | 在准备页或会中设备检测中开启麦克风并观察电平 |
| 扬声器试听 | 440Hz、低音量、约 0.8 秒测试音 | 点击“扬声器试听”，不回放麦克风声音 |
| 摄像头 Simulcast | LiveKit VP8 多层发布，180p/360p 加原始层；远端自动订阅 | 启用 SFU 后开摄像头；宫格请求中层，主画面优先高层 |
| 主持人静音 | 服务端保存限制，更新 SFU 发布权限并静音已有麦克风轨道 | 成员面板点击“静音”；“允许开麦”仅解除限制，由对方主动开麦 |
| 移出成员 | 清理在线连接和 SFU 成员，持久化本场移出限制 | 主持人在成员面板点击“移出”，确认后生效 |
| 结束会议 | 主持人鉴权、关闭信令与媒体房间，通知全员离会 | “结束会议”→确认；录制中先保存录制 |
| 会议记录 | 已结束列表、参会者、时间、聊天历史、录制列表 | 工作台“已结束”→“详情与回放” |
| 录制回放 | 主持人浏览器合成宫格/共享与混音，保存 WebM，参会者鉴权播放 | 会中“录制会议”→“停止并保存”，结束后打开详情回放 |
| 热插拔 | 自动刷新输入列表、失效设备回退默认输入；保留静音状态 | 插拔耳机/摄像头后查看设备面板，也可手动切换麦克风/摄像头 |
| 视图切换 | 响应式宫格、演讲者、共享主画面；支持固定成员 | 会中选择“画面布局”和“主画面” |
| 聊天增强 | 未读徽标、发送中、8 秒未确认、失败重试；服务端去重 | 切换到成员面板收消息可观察未读；断线恢复后可重试 |
| 服务端治理 | 用户/IP/WS 限流、JSON 可配置结构化日志、最大时长调度、退出等待 | 默认每场最长 240 分钟，每 5 秒调度；日志可用 `LOG_FORMAT=json` |

P2P 模式支持共享、设备、录制和页面会控，但**媒体服务端执行的静音/移出、SFU 转发和 Simulcast 验收必须使用 LiveKit 模式**。P2P 不具备阻止恶意自定义客户端直接传媒体的能力。

## 录制的具体边界

- 录制由主持人浏览器执行，所有参会者会看到录制提示；画面来自本场媒体轨道，不抓取其他桌面内容。
- 使用 Canvas 合成 1280×720、15fps 视频，Web Audio 合成音轨，MediaRecorder 输出 WebM。没有麦克风时添加零增益时钟源，避免 Chromium 生成空文件。
- 浏览器最多录制 30 分钟或约 80 MiB，达到限制自动停止保存；服务器单文件上限 96 MiB。
- 上传后保存 SQLite 元数据和私有文件；文件不放在静态目录，只有本场参会账号可以读取，下载接口支持 Range。
- 上传失败时保留本地备份下载；离会过程会等保存结果。空文件会明确报错，不提供无效备份。
- 关闭/刷新录制中的标签页可能丢失未保存片段，因此有离开页面提醒。长会议可分段录制；后台浏览器节流可能降低帧率，建议主持人保持会议页在前台。
- 这是浏览器合成录制，尚未接入 LiveKit Egress、对象存储、转码、自动清理和多份录制并发管理；不作为长期后台无人值守录制方案。
- 部分 Chromium WebM 的容器时长可能为不定长；页面展示数据库保存的实际录制时长，浏览器支持的拖动行为由解码器决定。

常规检查：

```powershell
.\scripts\check.ps1
```

真实 SFU 测试（先启动 LiveKit）：

```powershell
.\scripts\test-media.ps1
```

真实测试使用两个独立的 Go WebRTC 客户端，发布合成 Opus 音频，验证第二端收到 RTP，以及媒体端静音权限、移出和房间结束。不会访问用户真实设备。

常规前端测试覆盖 SFU 摄像头/音频/屏幕分源发布、Simulcast 参数、静音状态、重连状态、屏幕轨道停止、热插拔保留静音、录制上传与失败备份；Go 测试覆盖会控持久化、权限、录制鉴权/Range、会议超时和增量数据库扩展。

## 关键代码阅读顺序

1. `internal/media/livekit.go`：短期房间令牌、媒体管理接口，密钥仅留后端。
2. `internal/server/advanced.go`：会控授权、详情、超时任务。
3. `internal/store/advanced.go`：新增 moderation / recordings 表及查询。
4. `internal/server/recordings.go`：上传限制、私有路径与回放鉴权。
5. `web/src/hooks/useConference.ts`：统一 P2P / SFU，串行发布和订阅清晰度。
6. `useScreenShare.ts`、`useMedia.ts`、`useDeviceMeter.ts`：设备与共享生命周期。
7. `useRecording.ts`：合成录制、保存和备份；`HistoryDialog.tsx`：历史与回放。

## 已验证与仍需实测

- 已通过真实 LiveKit 1.13.11 的双客户端音频 RTP 转发及媒体会控测试。
- 已在浏览器完成无摄像头/麦克风的录制、保存、结束会议、历史查询和 WebM 回放；播放器解码 1280×720 且进度正常前进。
- 当前 Codex 内嵌浏览器的 SFU ICE 连接未建立，页面明确显示媒体连接失败；独立 Go 客户端连接通过。应使用桌面 Chrome/Edge 在实际网络中验证设备通话，不把信令连接正常等同于媒体连通。
- 本次没有采集真实摄像头、麦克风或桌面；真实屏幕选择、硬件热插拔、扬声器听感、浏览器 Simulcast 实际编码层、公网 NAT/TURN 与大规模负载仍需人工设备验收。
- 单进程 Hub 仍是演示架构；网络管理 API 有短超时。多实例需要共享状态与事件总线，生产还需要令牌撤销、持续会控对账、录制配额与文件清理。
- LiveKit 加入令牌为 2 分钟短令牌；应用拒绝被移出的账号重新领取。自托管媒体服务的旧令牌撤销能力取决于 LiveKit，正式部署应配合媒体事件/持续对账，不把应用拒绝加入当作永久撤销已签发媒体令牌。
